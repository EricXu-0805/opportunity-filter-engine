# Full Resume：方向、理由与同活动补充

## 现在支持什么

- 新目标稿保存完整 `base_snapshot.research_interests`。它是学生希望研究的方向，不是已掌握的技能或已完成的经历。
- 兴趣随文档签名、保存与恢复一起变化。旧稿缺少该字段时保持缺失；需要使用新方向时明确重建，不从旧 hash 推测内容。
- 兴趣进入全稿建议和选材提示，参与完整文档及提示容量检查。超限拒绝，不截断。导出正文只来自已确认的简历事实，不自动加入兴趣。
- 用户可选择一条活动经历和同活动补充，完整阅读后确认允许合用。后端仍核对来源，不把“确认关联”当作任意拼接的许可。
- 理由由建议类别与已核对的学生、目标原文组成。模型可以选择相关引用和建议类别，但自由编写的学生成就不会原样显示。

## 同活动来源合同

两类 API 请求可带 `support_groups`：

```json
[{"unit_id":"line-3","support_unit_ids":["line-4"],"confirmed":true}]
```

- 最多 24 组，每组最多 24 个补充来源。禁止重复目标、重复来源、引用自己、未确认或未知 ID。
- 目标和补充都必须是当前有效文档中、同一 activities block 的 experience；它们在母版 activities、education、publications 中只能有一个关联位置。
- 建议批次的目标必须在本批选中行内；选材计划的目标可在当前完整文档内。未选择的来源不能提供事实。
- 文档签名绑定所有原文、经历 ID 与 revision。前端接受时还须核对当前资料、文档和支持组；改变勾选不能继续接受旧结果。
- 请求显式提供该字段时，回执精确回显，包括空列表。未提供保持旧合同；显式 null 被拒绝。
- 有支持组的建议和计划改写携带完整 `source_evidence`：目标原句全文在前，补充按勾选顺序排列。偏移按 Unicode codepoint；保存到已有修改来源记录中。
- 这些引用记录“本次允许使用的来源”，不声称模型实际使用了每个来源。不能只存模型选中的短片段。

## 改写与容量

- 无支持组保持原来的单句来源规则。
- 有支持组时，来源仍分开保留主体、动作、对象、数字和限定语。不能把另一句的数字移到本句动作上，或把团队结果写成本人成果。
- 多来源采用有限的完整子句对应：允许已覆盖的动词词形、明确工具位置和 run/execute 等结构变化；无法对应的改写拒绝，原文仍可审阅。支持英文工具原文变化与中文原句保留，不是通用的中英文语义判断。
- 例如“写了 Python 测试”加“本人跑了 12 个测试用例”可以生成整合句；“审阅 12 项测试”加“采集 45 个样本”不能生成“审阅 45 项测试”。
- 单条改写最多 6,000 codepoints。计划中无组改写仍须短于原句和当前句；有组改写须短于“原句+全部补充”以及“当前句+全部补充”的总长度，可长于旧目标句本身。
- 建议批次按去重后的选中及支持原文核对 16,000 总字符、6,000 经历字符；完整提示另限 60,000 字符。计划发送完整 blocks，支持关系用 ID 指向已有原文，完整提示限 120,000 字符。所有限制拒绝超限输入，不默默删除来源。

## 理由与版本

- 理由类别包括方法、研究方向、可迁移经历、必要背景、篇幅取舍、较低关联和需人工对照。
- 系统说明建议动作及其考虑点，并显示经过范围与偏移校验的原文。未知旧式理由转为原文对照，不自由复述学生成就；有效改写和逐项建议继续保留。
- 建议版本 `full-target-v6`，选材版本 `full-target-plan-v5`，来源检查版本 `target-resume-source-checks-v5`。
- v6 建议：服务端从目标描述、要求、可用论文标题和官网段落切出编号引文（criteria 不切）；模型只能把原句词语连到引文，并声明改动（lead_with、relabel、verb_first、personal_first、tighten）。每条改写只用它原句的语言，不翻译；界面语言只决定服务端写的理由用中文还是英文。改写先过合同与事实锁，再过一次忠实度复核；未通过的经历行以 `unchanged` 保留原文并给出原因，复核未完成的是可重试的 `skipped/rewrite_unchecked`，目标没有可引用文字时为 `skipped/target_has_no_text`。支持组的补充句只能随上述改动逐字加入，长度上限按“原句+补充”计。
- 这些规则不验证经历实际发生、不证明语义匹配正确，也不覆盖任意改写。模型质量、当前云端资料和实际保存/恢复需各自证据。
