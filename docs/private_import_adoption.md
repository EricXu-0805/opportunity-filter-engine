# 将浏览器导入明确保存到账户

## 用户看到的流程

- 先在当前浏览器保存或更新导入记录，再点击“保存到账户”。打开页面不会上传。
- 每次审阅先读取账户副本的完整内容。已有副本时，同时展示旧内容与这次准备保存的内容；用户确认后才替换。
- 浏览器副本和账户副本彼此独立。此次保存成功不代表以后会自动同步，也不代表来源、资格或 AI 建议已核实。
- 版本冲突、读取失败或本地内容改变时，不自动重试覆盖。用户重新读取并审阅后，才能再确认。
- 已删除的账户记录保留删除标记。重新点击同一浏览器记录不会复活它，也不会偷偷换一个编号。

## 接口与保存依据

`usePrivateImportAdoption()` 返回 `state`、`prepare(entry, owner)`、`confirm()`、`cancel()`。`prepare` 只读；`confirm` 仅接受当前 `review` 状态。

审阅保存完整浏览器条目、完整候选机会、原始 owner token 和完整账户回执。调用开始时复制并冻结这些值；确认前、异步返回后及存储通知到来时，重新核对原账号和完整浏览器条目。只比 ID、时间或标题不足以通过检查。

账户编号由 `SHA-256(JSON.stringify(['ofe-private-import-adoption-v1', ownerId, localEntryId]))` 的前 16 字节生成 UUIDv8，再加 `private-import:` 前缀。同一账号、同一本地编号在重试、重载和不同标签页中得到相同编号。内容不参与编号。重新创建本地记录、其他设备重新导入会产生不同身份；本功能没有跨设备内容去重保证。

读取使用现有 private import SDK。首次保存传 `expected_revision=0`；更新传本次 GET 回执的精确 revision。服务端 CAS 冲突必须重新审阅。重复点击确认只发出一次保存请求。

## 失败与取消

- 账号变化：立即隐藏旧内容、取消当前请求；晚回包不能恢复旧账号内容。
- 本地记录删除、完整内容变化或损坏：阻止确认，保留原审阅供用户理解失败原因；不改写本地存储。
- 关闭或组件卸载：取消等待；StrictMode 重挂不会自动读取或上传。
- 本地编号散列等待单独限制为 30 秒。GET/PUT 使用 SDK 原有 30 秒等待限制，覆盖认证、请求及回执校验；这不是整个审阅流程合计 30 秒的承诺。
- 超时、取消、账号变化或本地修改发生在 PUT 已发出之后时，服务端可能已经保存。前端不能保证回滚，也不会宣称“一定未保存”；下一次显式 GET 用于核对结果。
- 网络、身份服务、存储和回执错误只显示固定错误码，不显示服务端异常正文。
