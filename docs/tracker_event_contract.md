# Tracker：状态、联系与时间（M45）

## 当前字段表示什么

| 数据 | 来源 | 可以说明什么 |
| --- | --- | --- |
| `interaction_type` | 用户选状态，或确认联系时首次建立记录 | 当前跟进状态；不单独证明某封邮件已发送 |
| `updated_at` | 状态、备注、提醒等记录修改 | 这条记录最后更新时间；不能当作联系或状态发生时间 |
| `last_contacted_at` | 用户点击“我已发送”后的服务端确认 | 最近一次联系确认的时间；不是从邮箱核实的实际发送时间 |
| `interaction_status_changes.changed_at` | 数据库状态变化记录 | 本次状态写入时间；不能当作邮件送达或教授回复原始时间 |
| 邮件背景 `sent_on` | 用户填写前信日期 | 本次跟进写作的已确认背景；不自动修改 Tracker |

## 页面规则

- 切换状态保留已有联系日期。没有日期时继续留空，不生成“现在”。备注、提醒和重试也不能补写联系日期。
- 状态历史使用实际返回的变化记录。只知道当前状态时显示当前状态，不从 `updated_at` 推出“刚刚已回复”。
- 加载中、成功但没有历史、读取失败分别显示；失败可重试。没有配置存储或身份未就绪不能当作成功空列表。
- 机会或账号变化后，旧读取结果不进入新页面。数据库读取仍按当前身份和机会过滤。
- 生成、精修、复制、打开邮箱和设置提醒不确认发送。确认成功才更新联系摘要；已有已回复、面试、拒绝等状态保留。
- 明确重新生成草稿后，旧稿的确认失败不显示在新稿上。旧稿成功保存的真实联系摘要仍传回父页面，新稿需要另行确认。
- 复制成功或失败提示只对应实际复制的正文版本；重建、手写或AI替换后不能沿用旧提示。延迟返回的复制结果也不能标记另一份正文。
- 确认保存失败只说明没有拿到成功结果，不能证明没有写入。提示用户先查看 Tracker，再决定是否重试。

## 当前不足，不能标成完成

- 一条机会只有联系摘要，没有逐封发送历史。收件人、主题、正文、附件和材料版本尚未绑定到独立联系事件。
- 发送确认是用户自述；未接入真实邮箱送达回执。暂未提供独立实际发送时间和确认时间。
- 同次弹窗防重复点击不等于跨设备、刷新和未知结果重试的事件去重；后续需要稳定事件编号及服务端去重。
- 模板切换、AI换稿及手动编辑仍属于当前草稿会话；逐份正文的发送确认与不可变材料快照需一起完善。
- 本地测试使用受控身份和HTTP响应。线上状态历史表、权限及实际邮箱行为需另行验证。

## 后续数据设计

以下为待实现建议，不是现有能力：

- 将联系事件与机会当前状态分开。事件保存稳定编号、目标、收件人、材料版本、用户提供的实际时间、系统确认时间和来源。
- 发送请求、服务商接受、送达、退信和用户手动确认分别记录；未得到结果时保留未知。
- 新事件不覆盖旧材料。用户更正通过追加更正说明保留历史；状态摘要由实际事件或明确用户操作更新。
- 先实现手动确认事件及重试去重，再接入逐封批准的发信流程。外部邮箱入口继续保留。
