# 邮件联系背景（M30、M33）

## 本次行为

- 首次联系：继续由服务端机会资料判断是明确岗位还是探索联系，用户不能把教授目录改成招聘空缺。
- 经人介绍：填写介绍人、实际介绍内容，并确认可以在信中提及。介绍不等于推荐或背书。
- 跟进前信：填写实际发出的前信并确认；日期可留空。回复情况默认“不确定”，不自动写成未回复。已回复需补充回复内容。
- 对方拒绝或要求不再联系时，界面暂停准备跟进，保留原稿。
- 可投入时间选填；填写后需确认。没有回答就不承诺每周线下工作或具体投入时间。

“应用背景”只确认本次写作输入，不生成、不发送、不标记已联系。更改任何背景字段即暂停旧写作请求；主题、正文、收件人和未提交修改要求仍保留。用户明确重新生成后才替换草稿，失败时保稿。换目标、关窗或换账号清除该会话的私密背景。

## 接口约定

四个入口共用顶层 `contact_context`：`/cold-email`、`/cold-email/stream`、`/cold-email/variants`、`/cold-email/refine`。不传时兼容首次联系。

```json
{
  "version": 1,
  "purpose": "follow_up",
  "follow_up": {
    "sent_confirmed": true,
    "previous_message": "实际发出的前信",
    "reply_status": "unknown"
  }
}
```

- `purpose`：`first_contact | referral | follow_up`，禁止混用其他用途的字段。
- `referral`：`referrer_name`（120 字符）、`referral_note`（1500 字符）、`confirmed: true`。
- `follow_up`：`sent_confirmed: true`、`previous_message`（4000 字符）、`reply_status: unknown | no_reply | received`；`sent_on` 为可选真实日历日期 `YYYY-MM-DD`；`received` 必须提供 `reply_text`（2000 字符），其他回复状态不接受回复正文。
- `availability`：可选 `text`（500 字符）与 `confirmed: true`。
- 完整规范 JSON 不超过 9000 Unicode 字符。超长或非法内容拒绝，不截断、不回显错误中的私密原文。
- 前端去除首尾空白，保留内部空白；服务端拒绝未规范化字符串。可选 null 省略。
- 响应和每个模板包含 `contact_context_receipt`：`version: 1`、`purpose`、`context_sig`。签名为递归按键排序、紧凑 JSON、Unicode 原文、UTF-8 的 SHA-256 十六进制值。前端校验目标和背景回执后才采用结果。

## 事实与生命周期

前信、回复和介绍内容仅为联系背景，不加入学生能力、成果或指标证据。服务端使用确认的联系事实构造开头；初稿、评判、修改、精修和失败回退共用同一背景。模型漏掉场景或增加未确认联系事实时，回到对应场景的模板。

背景变化进入材料版本、排队动作和缓存的绑定；A→B→A 仍是新会话版本，旧 A 的异步结果不能重新生效。背景确认与“我已发送”的联系人记录入口独立。不自动从 Tracker 导入前信或发送日期。

明确重新生成成功后，新稿需要单独确认发送。旧稿的确认回执仍可更新历史联系记录，但不能将新稿标为已确认；旧稿的复制回执也不能给新稿显示已复制或发送确认入口。填写背景、应用背景及复制本身都不写联系人记录。

## 仍需验收

- 联系与成果检查含有限英文规则，不能证明任意表达都真实。需真实样稿和人工逐句评审。
- 官网表单和申请入口已传给写作规则；自由文本中的特殊联系要求仍需结构化和单独验收。
- 跟进生成新草稿，尚未关联原邮箱线程。时间原文短语和泛化研究连接仍需改进语言质量。
- 个人贡献、论文阅读程度和附件事实尚未组成完整补问流程。M30、M33 保持进行中。
- 本地受控请求、模板输出和浏览器回归不等于真实模型质量、邮件投递或线上验收。

Tracker 的字段含义、确认失败和后续事件记录见 [Tracker 时间与事件约定](tracker_event_contract.md)。
