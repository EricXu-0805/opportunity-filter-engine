# 教授联系要求：到期刷新

## 实际入口

- `refresh_all` 在目录合并后，检查本次选中学校的 active 教授。研究方向、职称或邮箱齐全，也不跳过条件核对。
- 默认每 14 天重核；失败至少间隔 24 小时。遇到 429，本轮停止新请求，并保留更晚的 Retry-After。
- 只访问当前个人页和已保存、已绑定的来源页，不自动猜实验室地址，不调用研究补全、模型或浏览器。
- 快速模式和 national-only 模式明确跳过。缺少本地语料、无效身份或来源不可解析都不算“已核对”。

## 请求和进度

- 默认每轮最多 100 个 HTTP 请求、100 页尝试；重定向每一跳都占请求预算。可用 `--condition-max-requests`、`--condition-max-pages` 调整，0 不发请求。
- 共用本轮截止时间；到期后不再开始新请求。单次请求仍使用现有网络超时，并非硬实时中断。
- 按每页上次尝试时间排序，再按记录 ID、页面地址稳定排序。失败和成功分别记录，临时失败不能改写上次成功核对时间。
- `condition_refresh` 单独报告每校记录数、待核对页、请求、失败、延后及容量限制；不写入目录成功状态，不作为教授离职的依据。
- 发布判断核对学校范围、记录与页面数量、捕获结果和请求预算。未核对完可保留有效数据，但必须报告缺口。

## 保存和恢复

- 每页更新内存；每 20 个变化页或经过 60 秒时，原子保存一次完整语料。不是保存所选学校的子集。
- 正常结束或普通异常退出时，再保存剩余变化。保存失败不清空待保存计数，也不宣称完成。
- 进程被强制终止时，最多 19 个已变化页的尝试可能尚未落盘，下一次会重试。该上界以保存正常工作为前提；磁盘故障另报失败。
- 本地语料约 347 MB。100 个变化页若不触发 60 秒阈值，需要 5 次条件快照，后续主流程另有最终保存；因耗时触发的保存可能更多。这个估算不是完整库吞吐验收。
- 后续可用小型恢复日志减少整库写入；当前未实现逐页持久化日志。

## 仍需验收

- 真实网页抽查、历史来源回填、生产调度和告警。
- 预算与实际库规模是否能满足 14 日新鲜度目标。默认 100 请求不代表十几万条资料能及时刷完。
- 32 页记录上限和 8 个有效来源块达到上限后的人工处理；不得静默删除旧来源腾出空间。
- 报告中的最低轮次仅是请求预算的乐观下界，不含失败、重定向和额外页面成本；容量阻塞时不能给完成轮次。
