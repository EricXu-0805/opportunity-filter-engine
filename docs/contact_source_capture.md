# 申请条件来源：采集与保存

适用：机会资格、申请材料、截止日期和联系要求。研究快照仍使用原有独立结构。

## 每次抓取保留什么

- 原始网页段落、真实标题、实际来源 URL、对应记录 URL，以及成功核对时间。
- 教授来源另绑定姓名。项目列表页不能直接充当每个子项目的条件页。
- 不从摘要、旧的结构化字段或模型输出倒推“官网原文”。

采集结果写入内部字段 `contact_instruction_capture`：

| status | 含义 | contact_instruction_sources |
| --- | --- | --- |
| captured | 支持的页面中找到相关完整段落 | 新段落 |
| empty | 支持的页面已核对，没有相关段落 | 明确空列表 |
| unsupported | 页面结构或项目范围无法可靠识别 | 不提供替换段落 |
| failed | 请求失败 | 不提供替换段落 |

`attempted_at` 记录本次尝试。段落的 `checked_at` 只记录成功核对。两者不能互换，也不能从全站更新时间补出来源日期。

## 更新规则

- 同一记录、身份及 URL 未变：未抓取或暂时失败，保留旧段落和原核对时间。
- 成功核对为空：只清掉本次页面的先前段落，保留其他页面。后续失败不能恢复已清掉的段落。
- 确认页面身份不符、来源撤销、跳转到其他页面，或同页多个项目无法区分：停用本次请求页面的旧段落，保存原因。只有更晚的有效成功观察可恢复。记录整体身份或主 URL 改变时不继承任何旧页。
- 新旧身份、日期或绑定冲突：拒绝把新段落套到旧记录。
- 去重后仍需更新同一实体的来源。不能因为旧记录已经存在，就吞掉新出现的申请限制。

## 采集边界

HTML 通用适配器读取正文中的完整段落、列表和标题。正文还有未解析的相关字段、页面超限、登录页或错误页时，结果是 unsupported，不算“没有要求”。结构适配器可读取特定页面的原始字段，但字段标题必须来自网页。

公共接口不返回内部采集收据。用户看到的资格、材料和邮件限制由已绑定的原文重新计算，仍保留未知、过期、冲突等状态。

这批修复只通过离线网页、临时文件和本地调用链验证。实际语料尚未回填；不能把采集能力已有实现写成历史资料已核实。


## 多页状态（B56）

- `contact_instruction_pages` 保存每页最后尝试、最后成功和删除屏障；旧单页 receipt 与旧来源数组可迁移，迁移不补日期。
- 页身份使用 `requested_source_url` 与 `record_source_url`。成功来源的 `source_url` 仍是实际最终地址；错误跳转不会借错误落点撤掉另一页。
- 一页更新或清空不删除别页禁令。多个有效页面相互矛盾时保留冲突，不能只取最新页。
- 最多 8 个有效来源块、32 个页状态。超限保留原来源和删除屏障，并明确记录拒绝原因。拒绝尝试仍参与重试排队。
- `next_retry_at` 只用于失败重试，不能当成功核对时间。真实成功后不继续携带旧失败等待。
- 详细协议见 `contact_source_pages.md`。

## 仍待验证或接入

- 到期轮换按独立教授条件刷新入口执行，不依赖研究/email/title是否缺失；本地离线验证不等于已执行全库回填。
- URL 导入已接实际响应地址、原请求地址和读取时间；不能据此声称所有共享项目页都已分段。
- Berkeley 独立校园采集器、URAP/RSS 等其他入口仍需逐个处理。
- 学校共用采集代码已接入，不代表每所学校的网页结构均已实测通过。实际历史回填、定时调度和线上验收仍待完成。
