# 邮件与简历样稿评审

对应原清单 M35、M36、M44。更新：2026-09-25。
本文件规定怎样评样；测试通过、表格建好都不等于真实样稿验收完成。

## 每份样稿留下什么

- 样本编号、材料来源与使用授权；合成材料明确标为合成，姓名和联系方式可替换。
- 原始材料、已确认经历及修订号、目标资料与来源日期；缺失项也保留。
- 生成输入、原始输出、用户修改后的稿件；输入摘要用于确认没有换材料。
- 代码提交、生成规则版本、实际模型和配置；模板写 template，未调用模型不填模型成绩或费用。
- 耗时、实际调用数、可核对的用量/费用；不知道填“未记录”，不能填 0。
- 学生和评审人的意见分开记，姓名、日期、结论不得预填。AI 检查结果另列，不冒充人工意见。

## 逐句怎么评

| 项目 | 看什么 | 记录方式 |
|---|---|---|
| 事实 | 人、项目、技术、职责、时间、数字、论文状态是否各有对应来源 | 原句 → 来源编号/片段 → 正确、错误或无法确认 |
| 具体联系 | 目标问题或方法与哪段真实经历有关；仅是兴趣时是否说清 | 写出联系的两端；只有同一关键词不算证明 |
| 内容取舍 | 是否选了相关经历，是否漏了更有用的证据或必要限制 | 写出应保留/删去/补问的内容和原因 |
| 邮件请求 | 对方能否判断学生想申请什么、想了解什么或希望如何回应 | 标出请求；核对官网联系要求和是否确有岗位 |
| 自然和清楚 | 是否像本人会说的话，是否有重复、套话、无依据赞美 | 标出具体句子和修改，不能只给总分 |
| 简历表达 | 是否交代做了什么、本人负责什么及已有结果 | 没有量化结果可保留真实方法或产出，不补造数字 |
| 导出 | 同一确认版本的姓名、日期、章节、链接、文字提取、换页是否正确 | 单列 PDF/DOCX 和打开它的应用；文案合格不替代版式验收 |

关键事实错误先退回；表达评分不能抵消事实错误。建议保留“可用 / 修改后可用 / 不可用 / 未评”及理由，不计算掩盖错误的综合分。这是 OFE 的验收约定，不是大学发布的评分标准。

## 首轮必须覆盖的情境

| 情境 | 固定输入与必须核对的点 |
|---|---|
| 无科研经历 | 只有已确认技能和课程；不能自动生成做过的项目、训练任务或研究成果 |
| 跨专业 | 有一项真实方法经验、目标来自另一领域；可讨论迁移或学习意愿，不默认已具备该领域研究能力 |
| 明确岗位 | 保存岗位原文及申请方式；职位、要求与请求必须一致 |
| 仅教授资料 | 只有目录或研究介绍；可询问机会，不能写已经存在的 vacancy |
| 来源不足 | 教授方向、学生贡献或数字的含义不明；删去断言或明确补问，不填一个漂亮答案 |
| 转介 | 必须有本人确认的转介人和转介内容；现有接口没有相应确认字段时记为功能缺口 |
| 跟进 | 保存前信、实际发送时间和已有回复；不凭一段草稿判断已联系，缺上下文记为缺口 |
| 多项目简历 | A 项目的数字或技术不得转给 B；团队配合不得变成独立领导，投稿不得变成录用 |
| 人工改过的稿 | 对照原始事实评 AI 建议；未采纳的建议和失败回退不能覆盖人工稿 |
| 文件与语言 | 单栏、双栏、中英文、长经历和初学者原稿分别评；逐项查漏读、截断、章节遗漏及导出 |

## 当前可以复查的自动证据

- `tests/test_cold_email_writing_quality.py`：真实模板和公共接口的受控输入，核对技能声明没有自动扩成具体工作；捕获实际生成、修订和精修上下文。模型返回是固定替身，不评真实模型自然度。
- `tests/test_resume_writing_quality.py`：给公共入口返回受控错误建议，核对跨条目事实、职责升级和人工稿保留。通过只证明这些已列反例的处理。
- `tests/test_cold_email_claim_contract.py`、`tests/test_experience_evidence.py`：附件、论文阅读、技能等级、已确认经历来源及撤回的既有检查。
- 浏览器保存、版本隔离及导出测试另见批次验收记录；不以这些结果代替逐句评样。

剩余工作：收集获准的真实原稿，用实际模型生成并保留完整版本；让学生和熟悉申请的人分别评审，记录分歧及修改。转介、跟进、补问和跨项目语义核对缺口仍按原清单推进。没有这组证据，M36、M44 保持未完成。

## 方法来源

本轮于 2026-09-25 重读以下官方材料，转成上面的 OFE 检查项：

- Illinois OUR 建议邮件结合研究兴趣、相关课程/技能和清楚请求，并针对导师准备内容。篇幅和跟进间隔是参考，仍须遵守具体联系要求。[联系研究导师](https://undergradresearch.illinois.edu/resources/how-to-get-started/)
- MIT CAPD 建议用项目、行动和结果说明经历；OFE 只使用已有结果，不把量化建议变成补造数字的理由。[简历经历写法](https://capd.mit.edu/resources/resumes-writing-about-your-skills/)
- Harvard MCS 建议从已有材料出发，把 AI 输出当待核对建议，并检查事实和个人表达。[AI 与简历写作](https://careerservices.fas.harvard.edu/ai-resumes-and-cover-letters/)
